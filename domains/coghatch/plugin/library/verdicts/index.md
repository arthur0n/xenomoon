# verdicts — index

One line per record, sorted by filename: `- [<title>](<slug>.md) — <description>`

- [agent-address-pipeline-vs-relay](agent-address-pipeline-vs-relay.md) — An agent address whose function must act on the agent's answer (validate a closed JSON object, read the record back, format the reply) is its own pipeline; an address that only relays the agent's prose is the generic ask-agent function.
- [agent-files-readable-types-only](agent-files-readable-types-only.md) — A pipeline passes only image and PDF attachments to the agent as files and names every other attachment in the message text, because the model provider rejects other file types before any request.
- [agent-harness-login-conf-switch](agent-harness-login-conf-switch.md) — The agent harness's OIDC login is a conf switch: present client id turns it on with the client secret read from Secret Manager, absent means login off, and the boot script refuses any half-set combination.
- [agent-harness-serves-every-agent](agent-harness-serves-every-agent.md) — One agent harness serves every agent; a single Agent adapter is composed over the harness caller contract, and which saved agent serves which address is a code table, never env. _(amended)_
- [agent-layer-existing-service-not-agentkit](agent-layer-existing-service-not-agentkit.md) — Pipelines first called an existing private agent service synchronously, one workflow step per call, rather than adopting AgentKit, because the agents were fixed procedures with a closed JSON contract. _(superseded)_
- [agent-own-mailbox-credentials](agent-own-mailbox-credentials.md) — Each agent address was briefly its own mailbox with its own SMTP user and password, so an agent's mail went out as that agent. _(superseded)_
- [agent-per-email-address](agent-per-email-address.md) — Every agent gets its own email address served by one generic ask-agent function per agent; an email-triggered agent never lives inside another pipeline, and the agent contract stays trigger-neutral. _(amended)_
- [agent-sdk-adapter-only](agent-sdk-adapter-only.md) — The agent harness's TrueForge SDK is an exact-pinned runtime dependency imported only under its own adapter behind a contract; the first proof of a pipeline calling an agent used a real workflow function on a hand-sent event. _(amended)_
- [agent-turn-budget-and-cancel](agent-turn-budget-and-cancel.md) — Each agent has one time budget per question, fixed from the turn's server creation time; the wait polls until terminal or deadline, reads once more, then cancels the turn by id, so no turn runs after its caller stops waiting. _(amended)_
- [agent-turn-keyed-by-run-id](agent-turn-keyed-by-run-id.md) — One question is one agent turn, created once under keys taken from the workflow run id, so every retry of a run lands on the same session and the same turn and never creates a second one.
- [agent-ui-behind-proxy-single-caller](agent-ui-behind-proxy-single-caller.md) — The VM proxy forwards to the agent harness as a third upstream under one stripped path prefix for exactly one caller, the access hub; any other caller gets the same bare 401, enforced in code.
- [allow-list-and-dmarc-same-identity](allow-list-and-dmarc-same-identity.md) — An inbound mail is accepted only when the sender allow-list and DMARC name the same identity: the DMARC header.from domain must equal the domain of the single parsed From address.
- [attachment-type-sniffed-when-generic](attachment-type-sniffed-when-generic.md) — When a mail declares a generic binary type for an attachment, the receiver detects PDF, PNG or JPEG from the first bytes and carries that type; a specific declared type is believed, and the extension is never used.
- [auto-response-loop-brake](auto-response-loop-brake.md) — An automatic response is never answered, an address never answers itself, and every outbound mail declares itself automatic; the inbound refusal ends the run as completed before any step, so no alert mail is sent.
- [automation-connections-use-service-identities](automation-connections-use-service-identities.md) — Connections used by automations run as machine service identities (for example an ERP machine-to-machine client), never an employee's identity; per-user access exists only where an employee's own data is touched.
- [boot-config-agreement-gate](boot-config-agreement-gate.md) — The VM boot script and the app's config loader must agree, and the gate proves it by behaviour: it runs the real boot script on a conf holding every required key and loads the env file it writes with the real config loader.
- [ci-writes-digest-pins](ci-writes-digest-pins.md) — A digest pin is written by CI as a pull request, and the owner's merge of that pin PR is the one approval of a roll; the pin workflow trusts nothing in the dispatch payload beyond what it verifies against the registry and the source run.
- [connection-layer-in-process](connection-layer-in-process.md) — The connection layer stays in-process: no connection platform (Nango, OpenConnector, superglue) and no OAuth library; the connections package hand-writes each system's auth on one shared transport. _(amended)_
- [connection-requests-honour-caller-abort](connection-requests-honour-caller-abort.md) — Every connections request accepts an optional caller AbortSignal; an abort ends the call with no further attempt and is reported as its own non-retryable outcome, never a timeout.
- [connections-package-messages-consumer-neutral](connections-package-messages-consumer-neutral.md) — A message the shared connections package emits names no consumer, no consumer's deployment resource and no command; each consumer keeps its own remedy line where its operators read.
- [connections-package-separate-repo](connections-package-separate-repo.md) — Two repos: the platform (workflow app, infra, docs) and a published connections package shared by agents, pipelines and the ETL, because a package is the only shape that does not fork the connections. _(amended)_
- [container-stats-via-journal](container-stats-via-journal.md) — Per-container CPU and memory are sampled once a minute by a small script on a systemd timer and carried to Cloud Logging by the existing journald receiver; no Docker receiver, no cAdvisor.
- [contracts-and-adapters-per-capability](contracts-and-adapters-per-capability.md) — Each capability has one closed, types-only contract file and its own live and stub adapters; only a deployable's composition root imports adapters, and the gate enforces it. _(amended)_
- [dashboard-branding-frontend-only](dashboard-branding-frontend-only.md) — The workflow dashboard may be branded per client cosmetically, frontend only, with no backend change; the branded image is built by the client repo's CI, pinned by digest, and runs the same engine version.
- [erp-record-rest-in-connections-package](erp-record-rest-in-connections-package.md) — ERP record REST access lives in the shared connections package as a generic authenticated GET plus named per-resource readers and a generic verbatim create, because vendor paths and record shapes are connector shape, not domain content.
- [erp-write-idempotent-by-external-id](erp-write-idempotent-by-external-id.md) — An ERP create is idempotent by construction: a key derived from the triggering message is set as the record's external id, read before any POST and re-read after every refusal, so stacked retries never open a second record.
- [error-redaction-before-truncation](error-redaction-before-truncation.md) — Error redaction in the connections package is value-aware and runs before truncation: every thrown error scrubs secret patterns and the exact credential values used, on every path that renders a vendor body.
- [failure-alerts-one-shared-handler](failure-alerts-one-shared-handler.md) — Every workflow function is registered with one shared onFailure handler that mails the ops address with function id, run id, event id and error message only, never the payload or secrets.
- [failure-alerts-to-sender-and-ops](failure-alerts-to-sender-and-ops.md) — Failure alerts were first sent to both the forwarding employee and an ops address, since the forwarder can fix the input and ops needs the pattern. _(superseded)_
- [file-store-gcs-json-api-no-sdk](file-store-gcs-json-api-no-sdk.md) — The live file store uses the GCS JSON API over fetch with an ADC token, no storage SDK, into a temporary bucket with a 7-day delete lifecycle and create-only IAM, objects named by sha256 of their bytes. _(amended)_
- [file-store-signed-read-urls](file-store-signed-read-urls.md) — After each upload the file store mints a V4 signed read URL through the IAM signBlob API, with no downloaded key, valid 7 days to match the bucket lifecycle, so downstream readers need no credential.
- [how-to-runbooks-kept-alive-by-use](how-to-runbooks-kept-alive-by-use.md) — Keep two short checklist runbooks, one for a new pipeline and one for a new agent address, and fix whatever a checklist got wrong in the same commit as the work that used it.
- [image-prune-keep-current-and-previous](image-prune-keep-current-and-previous.md) — After every successful start the VM keeps only images named in the current and previous compose files and removes all others, off the restart's critical path.
- [image-retention-last-ten-deploys](image-retention-last-ten-deploys.md) — The image registry keeps the images of the last 10 deploys via keep-tags derived from git history on main, and deletes every other version older than 7 days.
- [images-built-in-ci-pinned-by-digest](images-built-in-ci-pinned-by-digest.md) — CI builds every image and pushes it to Artifact Registry; deployments name images by sha256 digest, never a tag, and vendor images are mirrored by digest, so no build credential lives on the VM. _(amended)_
- [inbound-body-size-cap](inbound-body-size-cap.md) — The inbound receiver caps the raw message at 5 MiB, checked before reading the body, and raises it only if a real user needs more.
- [inbound-dmarc-every-result](inbound-dmarc-every-result.md) — The Email Worker first required every DMARC result in Authentication-Results to be pass, because Cloudflare does not strip a sender's forged Authentication-Results header. _(superseded)_
- [inbound-dmarc-first-result](inbound-dmarc-first-result.md) — The Email Worker trusts only the first DMARC result in Authentication-Results, because Cloudflare prepends its own verdict and a sender cannot get ahead of it; per-sender exemptions were rejected.
- [inbound-email-technical-address](inbound-email-technical-address.md) — Email-triggered automations receive mail at a technical inbound address the platform receives itself, never a real mailbox, so pipelines need no mail permissions or per-user consent. _(amended)_
- [inbound-mail-as-event-no-polling](inbound-mail-as-event-no-polling.md) — The inbound receiver turns each received mail into an event; there is no mailbox polling and no mail subscription, because there is no mailbox to poll.
- [inbound-mail-cloudflare-email-worker](inbound-mail-cloudflare-email-worker.md) — Inbound mail arrives by Cloudflare Email Routing catch-all to an Email Worker that POSTs the raw message to a public Cloud Run receiver, which stores attachments and emits one event through the ID-token proxy; the domain is configuration, never code. _(amended)_
- [inbound-retry-no-ingestion-queue](inbound-retry-no-ingestion-queue.md) — No ingestion queue in front of the receiver: the Email Worker buffers the mail once and retries the receiver on network errors, 429 and 5xx with backoff before rejecting, because the workflow engine is already a durable queue.
- [inbound-routing-by-address-in-pipeline](inbound-routing-by-address-in-pipeline.md) — One inbound event and one contract for every mail; each pipeline subscribes with a trigger filter on its own address, which is one config value also used as its Reply-To, so the receiver knows no pipeline. _(amended)_
- [internal-proxy-tls-private-ca](internal-proxy-tls-private-ca.md) — The VM's auth proxy serves TLS only, with a server certificate signed by a private CA every caller trusts, because encryption of the Cloud Run to VM hop is implied by Google's docs, not documented. _(amended)_
- [legacy-deviations-ruled-at-port](legacy-deviations-ruled-at-port.md) — Deviations from a legacy flow's behaviour are build-time rulings taken one by one when each pipeline is ported, not up-front platform decisions.
- [machine-auth-entra-workload-federation](machine-auth-entra-workload-federation.md) — Machine callers present a Microsoft Entra app-only token to the agent harness, obtained by workload identity federation from the VM's Google identity, so no client secret, certificate or key file is stored.
- [mcp-tool-names-prefixed-per-server](mcp-tool-names-prefixed-per-server.md) — Tool names carry their MCP server's prefix and each MCP server has its own path, because the agent harness silently renames duplicate tool names across connectors and breaks enabled-tool lists with no error.
- [model-vendors-as-connections](model-vendors-as-connections.md) — Each model vendor is its own folder in the connections package with its own auth and endpoints, no vendor SDK and no shared abstraction across vendors; pipelines call it directly.
- [nightly-backups-postgres-redis](nightly-backups-postgres-redis.md) — Back up nightly with pg_dump of every database plus a Redis RDB snapshot, streamed by a systemd timer straight into a bucket the VM can only create objects in; a restore is rehearsed, because a backup never restored is not a backup. _(amended)_
- [no-retry-when-outcome-cannot-change](no-retry-when-outcome-cannot-change.md) — A retry that cannot change the outcome is not made: terminal agent turn outcomes are returned from the step and turned into a non-retriable error by the wiring, so the failure mail goes out within one budget.
- [one-function-per-pipeline-step-per-io](one-function-per-pipeline-step-per-io.md) — One Inngest function per pipeline and one step per I/O or transform, each step a plain tested function taking one JSON input, so every step can be rerun from the dashboard with edited input. _(amended)_
- [one-message-one-run-agent-owns-thread](one-message-one-run-agent-owns-thread.md) — An email worker is one mail equals one run, run-and-done, no orchestrator and no memory database; a reply is a new run carrying the thread id, and the agent owns the conversation. _(amended)_
- [one-model-provider](one-model-provider.md) — Use one model provider account and one secret for every agent and pipeline model call; model ids are config per call site, never literals in code. _(amended)_
- [ops-agent-journald-host-metrics](ops-agent-journald-host-metrics.md) — The Google Cloud Ops Agent runs on the VM with host metrics every 60 s and an explicitly configured journald receiver, because disk and backup alerts had no signal at all without it. _(amended)_
- [outbound-mail-smtp-submission](outbound-mail-smtp-submission.md) — Outbound automation mail was first sent by authenticated SMTP submission on port 465 to a hosted mailbox, because GCP blocks port 25 and adds no new vendor. _(superseded)_
- [outbound-mail-transactional-api](outbound-mail-transactional-api.md) — All outbound mail goes through one transactional mail HTTPS API (Postmark) with domain-level authorisation, one token and zero dependencies; the SMTP route was deleted, not kept as a fallback.
- [pipelines-run-one-at-a-time](pipelines-run-one-at-a-time.md) — Pipelines process one run at a time, so volume does not size the machine; the VM is sized by measured memory, not by run count.
- [roll-healthy-on-first-start](roll-healthy-on-first-start.md) — A roll is healthy only when the first docker compose up --wait exits 0; a first start that passes only on the unit's retry is a bug, and a failing container gets a healthcheck grace sized from its measured cold start.
- [sdk-validation-warning-redacted](sdk-validation-warning-redacted.md) — The generated SDK's schema-validation console warning, which can quote response body text, is replaced by one fixed line through a console.warn filter installed by the only module that builds the SDK client.
- [secret-expiry-labels-and-rotation](secret-expiry-labels-and-rotation.md) — Every long-lived secret the boot script reads carries an expires label, the hourly sampler logs its days-to-expiry, an alert fires 30 days before, and rotation is one new version plus one restart with the origin delete last.
- [shared-helpers-may-import-contract-types](shared-helpers-may-import-contract-types.md) — The shared helpers folder may import contracts as types only, giving the layering contracts then shared then adapters, pipelines and app, because helpers shared by two pipelines are often typed by a contract.
- [single-vm-to-start](single-vm-to-start.md) — Start with one VM running the workflow server, Postgres, Redis and the pipelines app; the server container gets no application secrets, only its own keys.
- [status-read-transport-failure-keeps-waiting](status-read-transport-failure-keeps-waiting.md) — A transport failure while reading an agent turn's status does not end the wait; it is logged as a category only and the turn is read again until the deadline, while a malformed status is a named terminal failure.
- [stub-adapters-test-only](stub-adapters-test-only.md) — Stubs came first for the proof of concept; from the MVP on, the composition root binds every live adapter and stub adapters are test doubles bound only in tests, never by an env switch.
- [thread-id-marker-in-mail-body](thread-id-marker-in-mail-body.md) — The conversation thread id travels in the mail body as a marker the question mail writes and the pipeline parses from the reply, restricted to a safe character set; the receiver knows nothing about threads.
- [vm-no-public-ip-cloud-nat](vm-no-public-ip-cloud-nat.md) — The VM has no public IP and reaches the internet through Cloud NAT, in a purpose-built VPC with ID-token verification at the VM and Direct VPC egress on callers, unless NAT egress volume turns out large. _(amended)_
- [workflow-engine-licence-internal-use](workflow-engine-licence-internal-use.md) — The self-hosted workflow engine's licence is accepted for internal use with no obligation; offering it to clients as a service needs a licence review first.
- [workflow-engine-self-hosted-inngest](workflow-engine-self-hosted-inngest.md) — The automation layer is self-hosted Inngest, because it is the only finalist that lets an operator rerun a failed run from a step with edited input on a deployed flow.
- [write-dry-run-gate](write-dry-run-gate.md) — Every write step (ERP POST, mail send) first sat behind a dry-run flag that logged the payload without posting, because no meaningful ERP sandbox was available. _(superseded)_
- [write-mock-in-connection](write-mock-in-connection.md) — The ERP write mock lives in the connections package behind one env switch mapping record type to an existing id; it is a tool to turn on when a run must not write, not a phase every write path owes.
- [writes-proven-by-one-real-run](writes-proven-by-one-real-run.md) — There is no dry-run gate; a new write path is proven by one real production run on records the owner names and cleans up after, and sending mail is not treated as a write. _(amended)_
