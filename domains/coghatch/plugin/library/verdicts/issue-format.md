# Issue format

## Decision

Every work issue carries: **driving decision · what · why · done when** (names the gate and the baseline totals)
**· not in scope · file set** (the allow-list the build step enforces, including every doc that cites the changed
files). The repo's issue template is that format; blank issues are disabled. One issue per piece: a piece of an area
issue gets its own issue before work starts. Search prior attempts before starting, log every attempt verbatim, and
resolve with cause and fix.

## Why

An issue that cannot name its done-when or its file set is a question, not work.
